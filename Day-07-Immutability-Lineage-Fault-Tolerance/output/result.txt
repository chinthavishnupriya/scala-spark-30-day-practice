--- Fault Tolerance ---
1. Spark records the lineage of every derived RDD.
2. If a partition is lost, Spark identifies the missing partition.
3. Spark recomputes that partition from the required parent RDDs.
4. Other healthy partitions do not need to be recomputed.
5. In this pipeline, Spark can rebuild a lost output partition by replaying the required transformations.

--- Conceptual Executor-Loss Simulation ---
Assume an executor holding one dailyRevenue partition is lost.
Spark would schedule the lost task on another executor.
The missing partition is recomputed from its lineage: salesRDD -> filter -> map -> map -> reduceByKey.
No manual reconstruction of the original dataset is required.

--- Performance Notes ---
Transformations are lazy until an action such as collect or count runs.
filter and map are narrow transformations.
reduceByKey is a wide transformation and creates a shuffle boundary.
Lineage provides fault recovery, while caching/persistence can reduce recomputation when reused data is available.
